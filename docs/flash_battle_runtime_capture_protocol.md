# Flash 1.12 战斗运行轨迹采集协议（待执行）

> 本文件是**采集规约**，不是原版运行证据。不得把 ActionScript 静态审计、Pygame/HTML5 自测或手工推测填作 Flash 原版观测。

## 原版身份和环境
- 仅使用仓库根目录 `game.swf`；预期 SHA256：`04b317b7fd9d32c5b083c993e99a3eea527f392e5fc938d23928e953bb638db9`。先实算核对，不匹配则停止。
- 记录播放器名称、版本、操作系统、启动参数、帧率/暂停方式、采集者、UTC 时间及原版录像文件 SHA256。
- FFDec 静态导出仅用于定位观察点，不代替播放器中的真实运行。
- 对每条轨迹保存可复现的起始存档或完整按键序列及其哈希；无法复现时标记 `unverified`。

## 最小独立场景
1. **必胜战斗**：从战斗前、进入、逐次扣血、动画结束、奖励发放到地图恢复，观察怪物是否消失。
2. **致死战斗**：从战斗前到 HP 归零或负值、死亡界面/重启、怪物与奖励状态，特别观察奖励是否仍被触发。
3. **边界**：恰好剩余 0 HP 的战斗（若原版可复现）；不能复现则记录原因，不能编造结果。

## 每一步 JSONL（原版与双端分别采集）
每行至少包含：
```json
{"schema_version":1,"source":"flash","case_id":"win_001","step":0,"action":"initial","floor":0,"x":0,"y":0,"hp":null,"money":null,"exp":null,"monster_id":null,"monster_present":null,"battle_phase":null,"game_over":null,"evidence_frame":null,"verified":false}
```
- `source` 必须为 `flash`、`pygame` 或 `html5`；`null` 表示**未观测**，不能当成零或 `false`。
- `step` 从 0 连续递增；`action` 保存原始按键或观察事件，三端采用同一动作序列。
- `evidence_frame` 指向录像帧号或截图相对路径；另附原始录像/截图的 SHA256 清单。
- `verified=true` 仅在该行所有非空观测值可从所附原版证据复核时使用；运行环境未验证则始终为 `false`。
- 记录原版是否以帧/异步回调推进；不能简单把不同帧上的临时状态当成机制差异。

## 验收门禁
- 先由独立复核者确认 Flash 录像、起始状态、动作顺序和最终状态可重现，再生成锁定的原版 JSONL。
- Pygame 与 HTML5 必须分别运行同一场景，输出独立 JSONL；逐状态对照生命、金币、经验、怪物存在、楼层/坐标、死亡与战斗阶段。
- 对每个首个差异保存：原版证据帧、双端对应帧、预期/实际、根因、最小补丁、回归命令与 CI 链接。
- 静态源码链 `Display_kill==2 -> Move_arrow(100)` **不证明**死亡路径、负 HP 或实际奖励行为。
- 完整地图动态事件、结局及视觉原版基线未验收前，不得开启 Gymnasium/Kaggle 训练，也不得宣称 1:1 完成。

## 本轮未完成项
- 尚无可复核的 Flash 胜利、死亡及 HP=0 实际轨迹。
- `mt_06` 的 946 处 RGBA 差异只有双端对比，缺少独立 Flash 视觉基线。
- 本规约本身不改变游戏逻辑、不增加已验证一致性范围。
